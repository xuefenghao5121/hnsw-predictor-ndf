# 安全红线

## 1. 绝对禁止的代码模式

以下模式**禁止**出现在任何代码中：

### 1.1 硬编码敏感信息
- ❌ 硬编码密码、API Key、Token、私钥。
- ❌ 硬编码数据库连接字符串。
- ✅ 必须从环境变量或密钥管理服务读取。

### 1.2 不安全的 SQL 拼接
- ❌ 使用字符串拼接构造 SQL 查询（易受 SQL 注入攻击）。
- ✅ 必须使用参数化查询或 ORM。

### 1.3 不安全的反序列化
- ❌ 反序列化不可信数据（如使用 `pickle.loads()` 处理用户输入）。
- ✅ 必须使用安全的序列化格式（如 JSON）。

### 1.4 日志泄漏
- ❌ 在日志中记录密码、Token、个人信息。
- ✅ 敏感字段在日志中必须脱敏（如 `password: ***`）。

## 2. 强制要求

### 2.1 输入验证
- 所有用户输入**必须**经过验证和清理。
- 验证规则应与 `spec/30-interfaces/` 中的字段定义一致。

### 2.2 权限检查
- 所有涉及资源访问的操作**必须**检查用户权限。
- 权限模型在 `spec/40-constraints/` 中定义。

### 2.3 审计日志
- 关键安全事件（登录、权限变更、删除操作）**必须**记录审计日志。

## 3. 安全审查触发条件

如果遇到以下情况，请主动提醒用户进行安全审查：
- 引入新的外部依赖（可能引入供应链风险）。
- 新增处理用户数据的接口。
- 修改认证或授权逻辑。
