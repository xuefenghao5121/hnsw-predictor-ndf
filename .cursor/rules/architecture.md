# 架构边界与依赖约束

## 1. 模块边界

本项目的模块边界定义在 `spec/10-architecture/modules.md` 中。

**重要原则**：
- **依赖方向**：依赖关系必须从高层模块指向低层模块，不允许反向依赖。
- **禁止循环依赖**：任何两个模块之间不得存在直接或间接的循环依赖。

## 2. 分层架构（如适用）

本项目的分层架构（Layered Architecture）：
┌─────────────────────────────────────────────┐
│ 表现层 (Presentation Layer) │ ← 处理HTTP请求/响应
├─────────────────────────────────────────────┤
│ 业务层 (Business Layer) │ ← 核心业务逻辑
├─────────────────────────────────────────────┤
│ 数据层 (Data Layer) │ ← 数据库访问、外部API调用
└─────────────────────────────────────────────┘

**分层依赖规则**：
- 表现层 → 业务层（允许）
- 业务层 → 数据层（允许）
- 数据层 → 业务层（**禁止**）
- 表现层 → 数据层（**禁止**）

## 3. 接口隔离

- 模块间的通信**必须**通过 `spec/30-interfaces/` 中定义的接口。
- 禁止一个模块直接调用另一个模块的内部实现。

## 4. 新增模块或依赖的流程

如果需要新增模块或引入新的外部依赖：

1. **首先**：在 `spec/10-architecture/modules.md` 中更新架构描述。
2. **其次**：通过 OpenClaw 提案流程确认。
3. **最后**：在获得确认后，再进行代码实现。
