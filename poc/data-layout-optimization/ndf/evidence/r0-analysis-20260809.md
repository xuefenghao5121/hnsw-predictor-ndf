# R0 Evidence: Data Layout Optimization Analysis

> 日期: 2026-08-09
> Trunk SHA: 3e98f3e
> 配置: 金标配置 A (SIFT1M M=16 EF=100, 256MB 1T cgroup)
> 分析方法: C++ 静态分析 + 理论建模

## 实验设计

对比三种 node ordering 的 cache locality：
1. **BFS** (当前)：广度优先搜索重排
2. **Random**：随机排列
3. **Original**：原始 hnswlib ID 顺序

分析工具: `/tmp/r0_locality.cpp`（加载完整 graph + BFS mapping，遍历所有节点的 layer-0 邻居列表）

## 核心数据

### Cache Line 分析（1M nodes, avg 21.2 neighbors/node）

| 指标 | BFS | Random | Original |
|------|-----|--------|----------|
| PQ CLs touched (mean) | 20.76 | 21.21 | 21.21 |
| CSR offset CLs touched (mean) | 19.96 | 21.20 | 21.18 |
| Neighbor ID spread (mean) | 329,088 | 901,074 | 854,201 |
| PQ reuse (nbrs/CL) | **1.02** | 1.00 | 1.00 |
| CSR reuse (nbrs/CL) | **1.06** | 1.00 | 1.00 |

**BFS 仅比 random 好 2-6%。几乎无 cache line sharing。**

### 根因分析

1. **PQ code = 32B = 半 cache line**。每 cache line 仅容纳 2 个节点的 PQ code。
   理论最优：21.2 neighbors / 2 = 10.6 CLs。实际 BFS：20.76 CLs（1.9x 差距）。

2. **BFS 降低了 ID spread（329K vs 901K）但不足以实现 cache line sharing**。
   BFS 使 graph 邻居的 new_id 更接近，但 "接近" 是万级，不是十级。

3. **Coleman 论文的 40% 提升不适用于我们**：
   - Coleman 场景：in-memory HNSW，full vectors (128×4B = 512B/vector)
   - 每个 vector 跨 8 个 cache line → reordering 影响大
   - 我们场景：PQ codes (32B/vector) → 每 vector 半个 cache line
   - 更 compact 的数据 → reordering 收益更小

4. **SoA layout 更差**：32 个 1MB 子数组，每次 pqDistance 触及 32 个独立 CL → 32x miss vs 1x。

### LLC Miss 建模

```
Measured LLC misses:     5,087/query
Estimated from PQ+CSR:   3,625/query
  - PQ codes: ~1,625/query (18.8% L3 hit, 6MB available)
  - CSR offsets: ~100/query (95% L3 hit)
  - CSR edges: ~1,900/query (3.2% L3 hit)
  - Difference (~1,462): block cache + flat_vec_cache + visited list + heap
```

### 改进天花板

即使 PQ cache line sharing 从 1.02 提升到 1.5（乐观假设）：
- PQ LLC miss 减少：~519/query
- 有效延迟节省（IPC=2.37，OoO 隐藏大部分 DRAM latency）：
  ~39 us/query → **4.1% QPS improvement**
- 低于 5% 可靠 A/B 测量阈值

## 结论

**Data layout optimization 的天花板太低，不值得做 POC 实验。**

1. BFS reorder 已经实施了，但仅提供 2-6% cache line reduction
2. 即使最优 layout（Coleman objective-based），PQ code 天然只有 32B → cache line sharing 受限
3. 理论最大改进 ~4% QPS，低于可靠测量阈值
4. SoA layout 更差（32x 更多 CL 触及）

**R0 REJECTED — 天花板不足。**

### 真正的优化方向

LLC miss 的根因是数据结构总量（284MB）>> L3（30MB），这不是布局能解决的。
需要的是**减少数据量**或**改变访问模式**：
- 更激进的压缩（4-bit PQ, 但精度损失）
- 减少 graph degree（降低搜索精度换取速度）
- 分层数据放置（hot nodes in cache, cold on disk）
