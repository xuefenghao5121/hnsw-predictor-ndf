# R2: mmap + WILLNEED 预取

> 日期: 2026-08-07
> Topic: csr-on-disk

## 配置

- mmap + MADV_RANDOM + 可选 madvise(MADV_WILLNEED) 预取
- `CSR_PREFETCH=1` 开启预取（每次 getInMemNeighbors 后对邻居 CSR 页做 WILLNEED）
- `CSR_PREFETCH=0` 关闭预取（默认，等同于 R0 mmap）

## 结果

| 配置 | 预取 | RSS init | 聚合 QPS | 稳态 QPS | Recall |
|------|------|---------|---------|---------|--------|
| 512MB 1T | off | 113MB | 848 | 944 | 96.00% |
| 512MB 16T | off | 113MB | 3,402 | 4,773 | 96.00% |
| 256MB 1T | **on** | 57MB | **562** | 591 | 96.00% |
| 256MB 16T | off | 90MB | 1,604 | 1,826 | 96.00% |
| 256MB 16T | on | 90MB | 1,206 | 1,269 | 96.00% |

## 分析

### 预取的双面性

| 场景 | 预取效果 | 原因 |
|------|---------|------|
| 256MB 1T | **+59%** (356->562) | page cache 极度紧张，预取减少同步 page fault |
| 512MB 1T | -15% (993->848) | page cache 充足，madvise syscall 开销 > 收益 |
| 512MB 16T | -3% (3,288->3,402) | 噪声内（16T 多线程掩盖 I/O 延迟） |
| 256MB 16T | -27% (1,650->1,206) | 多线程下 madvise 竞争加剧 |

**结论：预取仅在低线程 + 极紧 cgroup 下有价值。默认关闭，opt-in。**

### 256MB 1T 仍不达标

即使开启预取（-47.9%），仍超过 30% 阈值。
根因：256MB cgroup 下 page cache 预算 ~186MB，无法同时容纳 44MB CSR + 496MB vecblocks。
这是物理约束，非算法问题。

### 512MB 全配置达标

- 1T: -24.9% ✅ (< 30%)
- 16T: -18.2% ✅ (< 30%)

## 验收（更新）

| 条件 | 结果 |
|------|------|
| recall ≥ 95% | ✅ 96.00% |
| QPS 下降 < 30% (512MB) | ✅ -18.2% ~ -24.9% |
| RSS 下降 ≥ 40MB | ✅ -44MB |
| 256MB 可工作 | ⚠️ 16T 达标 (-19.2%), 1T 不达标 (-47.9%) |

## 结论

方案 A (mmap, 无预取) 是 512MB + 256MB 16T 的最优选择。
方案 C (mmap + WILLNEED 预取) 仅在 256MB 1T 有价值（+59%），但仍不达标。

**推荐 promote 策略**：
- 512MB 全配置 + 256MB 16T: promote 方案 A (mmap, CSR_PREFETCH=0)
- 256MB 1T: 记录为已知限制（page cache 物理约束）
- CSR_PREFETCH: opt-in 环境变量，低线程 + 紧 cgroup 场景可用
