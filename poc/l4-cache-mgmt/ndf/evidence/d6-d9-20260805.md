# Evidence: D6 (readahead window) + D9 (DEEP10M skipped)

> 日期: 2026-08-05

## D6: readahead 窗口大小调优 (MAX_MERGE_PAGES)

### 512MB 16T

| 配置 | QPS | vs no-merge |
|------|-----|-------------|
| no merge | 30,719 | baseline |
| merge unlimited | 27,099 | -11.8% |
| merge max=2 | 29,818 | -2.9% |
| merge max=4 | 19,840 | -35.4% (噪声) |
| merge max=8 | 30,022 | -2.3% |

### 256MB 16T

| 配置 | QPS | vs no-merge |
|------|-----|-------------|
| no merge | 15,920 | baseline |
| merge unlimited | **19,296** | **+21.2%** |
| merge max=4 | 14,170 | -11.0% |

### 结论

窗口限制无帮助。512MB 退化根因不是单次 readahead 窗口过大，而是排序操作本身的固定开销。
256MB unlimited 仍是最优。
