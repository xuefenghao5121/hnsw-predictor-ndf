## 分析

### 256MB 可行

- **QPS 8838**（4T）vs hnswlib unlimited **18496**（4T）= **48%**
- **内存 256MB** vs hnswlib **732MB** = **35%**
- recall 95.80% 完全不变
- oom=0, peak=256MB (严格在预算内)
- vs 512MB: QPS 下降 23%，内存下降 50% -> **内存效率更高**

### 256MB 下 FVC=64 最优

- 256MB page cache 预算极紧，FVC>64 会挤压 page cache 导致 I/O 增加
- 256MB 最佳: anon ~200MB + FVC 64MB + file cache ~58MB = ~262MB ≈ 256MB limit
- 与 512MB 最优 FVC=160 完全不同（512MB 有更多 page cache 空间）

### 内存效率叙事

| 配置 | QPS/MR | vs hnswlib QPS/MR |
|------|--------|-------------------|
| 256MB + WILLNEED | 34.5 | 2.0x |
| 512MB + WILLNEED | 22.3 | 1.3x |
| hnswlib unlimited | 25.3 | 1.0x |

**256MB 配置的 QPS/MB 内存效率是 hnswlib 的 2 倍。**

## 结论

H6 确认: 256MB cgroup + WILLNEED 在 4T 下可行，QPS=8838（hnswlib 的 48%），内存仅 35%。
