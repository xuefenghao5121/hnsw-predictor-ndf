# Evidence: Direction 1 - flat_vec_cache 调优

> 日期: 2026-08-05
> 协议: [[CON-SLA-014]] SIFT1M 512MB cgroup, 4T
> 方法: sweep FLAT_VEC_MB = 64/96/128/160/192

## 结果

| FLAT_VEC_MB | QPS | Recall | vs 基线 | P99(ms) | RSS(MB) | anon(KB) | file(KB) |
|-------------|-----|--------|---------|---------|---------|----------|----------|
| 64 (基线) | 9,252 | 95.80% | 1.00x | 0.65 | 202 | 400 | 310,080 |
| 96 | 10,717 | 95.75% | +15.8% | 0.65 | 211 | 408 | 301,056 |
| 128 | 9,975 | 95.75% | +7.8% | 0.63 | 216 | 420 | 295,424 |
| **160** | **11,421** | 95.75% | **+23.4%** | 0.67 | 220 | 424 | 292,096 |
| 192 | 9,741 | 95.75% | +5.3% | 0.62 | 222 | 428 | 289,408 |

cgroup_peak=512MB, oom=0 全部通过。

## 分析

### 最优点 FLAT_VEC_MB=160

- QPS 11,421 vs 基线 9,252 = **+23.4%**
- vs hnswlib unlimited 4T (18,496): **62%**（基线 52% -> +10pp）
- recall 不变 (95.75%)
- 更多上层向量常驻内存 -> 减少 FineRerank pread 次数
- page cache 仅减少 18MB (310MB -> 292MB)，未显著影响 I/O

### 非单调性

QPS 不是随 FLAT_VEC_MB 单调递增：
- 64 -> 96: +15.8%（热向量命中率提升）
- 96 -> 128: -6.9%（测量噪声？page cache 开始受压）
- 128 -> 160: +14.5%（命中更多向量）
- 160 -> 192: -14.7%（page cache 被挤压，I/O 增加 > cache 收益）

**拐点在 160MB**：flat_vec_cache 收益与 page cache 挤压的平衡点。

### 内存预算分析

512MB cgroup 内：
- anon (固定): ~200MB (图 + PQ + 代码)
- flat_vec_cache: 64-192MB (调优项)
- page cache (file): 剩余预算 ~120-310MB
- 最优分配: flat_vec_cache=160MB + page cache=292MB

## 结论

**H1 确认**: flat_vec_cache 调大可减少 FineRerank I/O，提升 QPS >5%（实测 +23.4%）。
最优值 FLAT_VEC_MB=160，可作为 promote 候选。
