# R3–R5: 规模收敛、cgroup 扫描、优化开关 sustained 复测

> 日期: 2026-08-06
> Topic: sustained-query-benchmark
> Baseline Trunk: `4a33f38`
> 隔离协议: [[CON-SLA-014]] via [[API-016]]
> 数据: 官方 SIFT 10K query 池 + 官方 GT（无 self-match）

## R3: 规模扫描 —— 稳态与 N 无关

512MB cgroup, 1T, seed=42：

| N | R | 聚合 QPS | 末轮 QPS | Recall@10 | 池覆盖 |
|---|---|---------|---------|----------|--------|
| 200 | 30 | 1,250.7 | 1,669.3 | 96.15% | 4,550 / 10,000 |
| 1,000 | 15 | 1,483.1 | 1,722.1 | 96.00% | 7,942 / 10,000 |
| 10,000 | 5 | 1,548.3 | 1,649.3 | 96.06% | 10,000 / 10,000 |

**关键发现：稳态 QPS 与 N 无关**（1,649–1,722，跨度 4%，在噪声内），
recall 稳定 96.0–96.15%。

这是方法论有效性的强证据：无论每轮采 200 / 1,000 / 10,000，
只要跑到稳态，测得的都是同一个物理量 —— 真实 sustained 吞吐。

聚合 QPS 随 N 增大而升高（1,251 → 1,483 → 1,548），是因为 N 越大，
Round 1 冷启动在总量中占比越小，与稳态无关。

**推论**：日常回归可用 N=1000/R=15（约 40s），无需跑满 10K。

**recall 在全部 6 组配置下恒为 96.00%** —— 采样池与 GT 一致，

| 配置 | 200q+warmup (现 SLA) | sustained 稳态 | 高估倍数 |
|------|---------------------|---------------|---------|
| 512MB 1T | 3,241 | 1,729 | 1.87× |

高线程数下高估最严重（16T 达 4.5–7.6×）—— warmup 使全部线程命中

## R5: ADAPTIVE_EF / LEARNED_EF sustained 复测 ★★★

N=1000, R=15。这是本 POC 最关键的实验：两个已 promote 的优化开关
在**诚实**测量下是否真的有效？

| cgroup | 线程 | 模式 | 聚合 QPS | 稳态 QPS | Recall | vs BASE (聚合) |
|--------|------|------|---------|---------|--------|--------------|
| 256MB | 4T | BASE | 2,200.0 | 2,526.8 | 96.00% | — |
| 256MB | 4T | ADAPTIVE | 2,822.1 | 3,414.7 | 95.81% | **+28.3%** ✅ |
| 256MB | 4T | GBDT | 2,197.5 | 2,358.8 | 95.99% | **−0.1%** ❌ |
| 256MB | 16T | BASE | 2,102.1 | 2,414.2 | 96.00% | — |
| 256MB | 16T | ADAPTIVE | 2,763.1 | 3,420.1 | 95.81% | **+31.4%** ✅ |
| 256MB | 16T | GBDT | 2,139.8 | 2,460.2 | 95.99% | **+1.8%** ❌ |
| 512MB | 4T | BASE | 3,910.3 | 5,258.9 | 96.00% | — |
| 512MB | 4T | ADAPTIVE | 4,397.7 | 6,161.1 | 95.80% | **+12.5%** ✅ |
| 512MB | 4T | GBDT | 3,874.1 | 5,119.7 | 95.99% | **−0.9%** ❌ |
| 512MB | 16T | BASE | 4,455.3 | 6,806.0 | 96.00% | — |
| 512MB | 16T | ADAPTIVE | 5,633.1 | 9,560.4 | 95.80% | **+26.4%** ✅ |
| 512MB | 16T | GBDT | 4,456.6 | 6,923.6 | 95.99% | **+0.0%** ❌ |

### 结论 1：ADAPTIVE_EF ([[BEH-033]]) 有效 ✅

sustained 场景下 **+12.5% ~ +31.4%**，recall 95.80–95.81%（仍 ≥95%）。

且 512MB 下也有收益（+12.5% / +26.4%）—— 这**推翻**了此前
"512MB 下 I/O 非瓶颈、Adaptive 无收益甚至略退" 的判断。
那个判断来自 cache-warmed 测量：warmup 后 512MB 确实没有 I/O 压力，
所以看不到收益。诚实测量下 512MB 依然是 I/O bound。

### 结论 2：GBDT / LEARNED_EF ([[BEH-034]]) 无效 ❌

sustained 场景下增益 **−0.9% ~ +1.8%**（全部在噪声内），**收益消失**。

对比此前 base-sampled 10Kq 测得的 +33~124%：

| 场景 | GBDT 增益 | 测量有效性 |
|------|----------|-----------|
| 200q + warmup | +3.3~6.0% | ❌ cache-warmed |
| base-sampled 10Kq | +33~124% | ❌ self-match 污染 GT |
| **官方池 sustained** | **−0.9~+1.8%** | ✅ 诚实 |

**根因分析**：GBDT 模型的训练数据来自 base-sampled 10K query 的 profiling。
那批 query 因 self-match 而"异常容易"（GT top-1 就是自己，距离 0），
模型学到的"所需候选数"分布因此系统性偏低。用在官方 query 上，
预测值不再匹配真实难度，`learned_limit` 的裁剪失去准确性 → 收益归零。

这是一个**训练集污染导致模型失效**的典型案例：
self-match bug 不仅污染了 recall 指标，还污染了 GBDT 的训练标签。

### 结论 3：ADAPTIVE 与 GBDT 的本质差异

| | ADAPTIVE_EF | LEARNED_EF (GBDT) |
|--|------------|------------------|
| 依据 | 运行时 PQ gap_ratio（在线信号） | 离线训练的模型（静态） |
| 对 query 分布的依赖 | 弱（自适应） | 强（训练分布） |
| 训练数据污染影响 | 无（无训练） | 致命（标签偏移） |
| sustained 收益 | +12.5~31.4% ✅ | −0.9~+1.8% ❌ |

在线自适应信号对分布漂移鲁棒；离线学习模型对训练集质量敏感。

## 命令

```bash
# R3 规模扫描
for N in 200 1000 10000; do
  R=30; [ "$N" = 1000 ] && R=15; [ "$N" = 10000 ] && R=5
  TAG=r3ss CGROUP_MB=512 THREADS=1 PER_ROUND=$N ROUNDS=$R \
    bash poc/sustained-query-benchmark/run_sustained.sh
done

# R4 cgroup 扫描
for MB in 512 256; do for T in 1 4 16; do
  TAG=r4 CGROUP_MB=$MB THREADS=$T PER_ROUND=1000 ROUNDS=15 \
    bash poc/sustained-query-benchmark/run_sustained.sh
done; done

# R5 开关复测
EXTRA="export ADAPTIVE_EF=1 ADAPTIVE_EASY_GAP=1.006 ADAPTIVE_EASY_EF=50 \
       ADAPTIVE_HARD_GAP=1.002 ADAPTIVE_HARD_EF=200"   # ADAPTIVE
EXTRA="export LEARNED_EF=1 GBDT_MARGIN=0.8"             # GBDT
```
