## 2. 一致性验证

### 2.1 现有 200q 是官方 query 池的前 200 个

```
官方 query: (10000, 128)
现有 200q:  (200, 128)
现有 200q == 官方前 200: True   ✅
```

**结论**：现有所有 SLA 基于的 200q 确实是标准 SIFT query set 的前 200 个，
**不是 base-sampled**，因此无 self-match 污染。这解释了为何 200q recall
（95.75%）可信，而 base-sampled 10Kq recall（89.7%）不可信。

### 2.2 官方 GT vs 现有 gt200

```
官方 GT[0][:5]:   [932085 934876 561813 708177 706771]
现有 gt200[0][:5]: [932085 934876 561813 708177 706771]

逐元素比较: 14/200 行有差异，26/2000 元素不同
集合比较:   198/200 行集合完全相同
```

差异分析：

| 类型 | 行数 | 原因 |
|------|------|------|
| 排序差异（集合相同） | 12 | 等距邻居的 tie-breaking 顺序不同 |
| 集合差异 | 2 | 完全等距的不同点被选中 |

集合差异的两行经距离验证：

| 行 | official 独有 | existing 独有 | dist² |
|----|--------------|--------------|-------|
| 93 | base[274922] | base[196106] | 都是 42192.0 |
| 170 | base[196049] | base[274865] | 都是 40644.0 |

**结论**：两者 dist² 完全相同，属于 exact tie。recall 计算不受实质影响
（任选其一都是正确的第 k 近邻）。**官方 GT 为权威，POC 采用官方 GT**。

### 2.3 self-match 检查

标准 SIFT query set 是独立采集的查询向量，**不在 base 中**。
与被拒的 base-sampled 方案根本不同：

| 方案 | query 来源 | self-match | recall 可信 |
|------|-----------|-----------|------------|
| 标准 query set | 独立采集 | ❌ 无 | ✅ |
| base-sampled（已拒） | 从 base 抽取 | ✅ 有（GT top-1 恒为 self） | ❌ |

## 4. 关键洞察

现有 200q SLA 的 recall（95.75%）**本来就是可信的**——问题只在 QPS
（cache-warmed 假象），不在 recall。

而 base-sampled 10Kq 的问题是**双重的**：
1. 破除了 cache 假象（这部分是对的）
2. 但引入了 self-match 污染（这部分是错的）

本 POC 的方案同时解决两者：标准 query 池（解决 self-match）+ 多轮随机采样
（解决 cache 假象）。
